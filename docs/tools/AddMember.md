# AddMember

## Description

AddMember adds a new member (method, property, field, constructor, or event) to an existing type while preserving the class structure and formatting. It uses Roslyn's syntax tree manipulation to intelligently place the new member among its peers—fields together, methods together, etc.

Smart insertion logic automatically places members in appropriate locations based on type (fields first, then constructors, properties, methods), or you can specify an exact insertion point.

## Comparison with Native Claude Code Tools

### vs Write tool
- **Write** requires reading the entire file, manually inserting the member at the correct location with proper indentation, then writing back the complete content
- **AddMember** locates the type semantically, determines optimal insertion point automatically, and inserts with proper formatting
- **Write** requires knowing the exact file path and current file structure
- **AddMember** works with just the type name (no file path needed)
- **Write** risks breaking syntax if indentation/braces are wrong
- **AddMember** validates syntax and handles formatting automatically

### vs Edit tool
- **Edit** requires reading the file first, finding an insertion point via text search (error-prone), crafting the exact string with proper indentation
- **AddMember** uses semantic understanding to find the type and insert intelligently
- **Edit** needs you to know where to insert (after which member?)
- **AddMember** smart insertion places members with their category automatically

### When to use AddMember
- Adding methods/properties/fields to existing classes without reading the entire file
- Leveraging AI code generation for method implementations
- Ensuring members are placed in conventional locations (fields first, then properties, then methods)
- Working with large files where reading wastes tokens
- Generating XML documentation automatically for public members

## Real-World Example

### Scenario
Add a `Subtract` method to the `Calculator` class with AI-generated implementation.

**Target:**
```csharp
public int Subtract(int a, int b)
{
    var result = a - b;
    _history.Add(result);
    return result;
}
```

### Approach 1: Using Native Write Tool

**Step 1: Find the file**
```
Glob(pattern: "**/*Calculator.cs")
```
**Result:** `SharpOps.Examples\Calculator.cs`
**Tokens:** ~50

**Step 2: Read the entire file**
```
Read(file_path: "D:\repos\RoslynMcpServer\SharpOps.Examples\Calculator.cs")
```
**Result:** Full file content (30 lines, ~400 tokens)

**Step 3: Manually determine insertion point**
You must analyze the file structure to decide where to insert:
- After the `Add` method?
- Before `AddToHistory`?
- Must count lines, preserve indentation, add proper spacing

**Step 4: Write back entire file with new method**
```
Write(
  file_path: "D:\repos\RoslynMcpServer\SharpOps.Examples\Calculator.cs",
  content: "<entire file with new method inserted at correct line with exact indentation>"
)
```
**Tokens:** ~500 (entire file content)

**Total: ~950 tokens, 4 steps, high error risk**

**Risks:**
- Must preserve exact indentation (spaces vs tabs)
- Easy to break syntax with mismatched braces
- Must manually place method in logical location
- Any mistake requires re-reading file

### Approach 2: Using AddMember (Manual Mode)

**Step 1: Add the method**
```
AddMember(
  typeName: "Calculator",
  memberCode: "public int Subtract(int a, int b)
{
    var result = a - b;
    _history.Add(result);
    return result;
}",
  comment: "Subtracts two integers and returns the result"
)
```
**Total: ~150 tokens, 1 step**

**Benefits:**
- No file path needed
- No need to read entire file
- Automatic placement after other methods
- Indentation handled automatically
- XML doc comment generated from plain text

### Approach 3: Using AddMember (Auto Mode) ✨

**Step 1: Let AI generate the implementation**
```
AddMember(
  typeName: "Calculator",
  memberCode: "public int Subtract(int a, int b)",
  auto: true,
  comment: "Subtracts two integers and returns the result"
)
```
**Total: ~80 tokens, 1 step**

**Response includes:**
```json
{
  "autoGenerated": true,
  "autoGenerationFailed": false,
  "generatedCode": "public int Subtract(int a, int b)\n{\n    var result = a - b;\n    _history.Add(result);\n    return result;\n}"
}
```

**Review workflow:**
1. Check `autoGenerationFailed` - if `true`, model couldn't generate (use manual mode or UpdateMethod)
2. Review `generatedCode` - verify the logic is correct
3. If wrong, use `UpdateMethod` to fix (this correction becomes training data)
4. If correct, done!

### When Write is Better
- Non-C# files (JSON, XML, markdown)
- Creating entirely new files
- Need to modify multiple members simultaneously
- Working with non-code content

## How It Works

### Mode 1: Manual Mode (auto=false or omitted)
The tool takes a type name and member code, uses Roslyn to load the solution and find the type by semantic search. It parses the provided member code into a syntax node (method, property, field, etc.) and validates it's well-formed.

Smart insertion logic determines placement:
- **Fields** → inserted at start (after other fields)
- **Constructors** → after fields
- **Properties** → after constructors
- **Methods** → after properties
- **Nested types/events** → at end

Or you can specify `insertionPoint`:
- `"start"` - very beginning
- `"end"` - very end
- `"after-fields"` - after all fields
- `"after-constructors"` - after all constructors
- `"after-properties"` - after all properties
- `"before-methods"` - before first method

The member is inserted with proper trivia (spacing/newlines), formatted via Roslyn's formatter, and if a `comment` is provided, an XML doc comment is generated with `<summary>`, `<param>`, and `<returns>` tags.

### Common Workflow

**For properties/fields:**
```
AddMember(typeName: "MyClass",
          memberCode: "public string Name { get; set; }",
          comment: "Gets or sets the name")
```

**For constructors:**
```
AddMember(typeName: "MyClass",
          memberCode: "public MyClass(string name) { Name = name; }",
          insertionPoint: "after-fields")
```

### XML Documentation
If you provide a `comment` parameter with plain text, the tool generates proper XML doc comments:

**Input:**
```
comment: "Adds two numbers and returns the sum"
```

**Generated:**
```xml
/// <summary>
/// Adds two numbers and returns the sum
/// </summary>
/// <param name="a"></param>
/// <param name="b"></param>
/// <returns></returns>
```

Public members automatically get stub XML docs even without a comment (empty summary/param/returns tags).

### Integration with Fine-Tuning
- **Manual AddMember** → Code IS collected for training
- **Auto AddMember** → Code is NOT collected (model output shouldn't train itself)
- **UpdateMethod after auto** → Correction IS collected (teaches the model)

This creates a virtuous cycle: model tries → you correct → model improves.

The tool handles all complexity of workspace management, syntax tree manipulation, smart placement logic, formatting, and file I/O, exposing a simple type-name-based interface.
